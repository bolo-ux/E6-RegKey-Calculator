# 破译方法论 / Reverse-Engineering Write-up

> 本文档记录本地注册校验算法的完整分析过程，作为安全研究方法学示例。
> **不含任何厂商固件、厂商源代码或专有数据**；只描述分析步骤、工具与结论。
> 使用限制见 [DISCLAIMER.md](../DISCLAIMER.md)。

## 1. 目标与约束

- **目标设备**：E6 robot controller（STM32F405RG，Cortex-M4F）
- **目标**：理解 E013/E014 两个参数的生成算法，以便在自有设备上恢复被 UID 绑定加密的参数区
- **已知线索**：设备未注册时屏幕显示 `产品未注册!` 与 `您的机器码为: XXXX`
- **材料**：设备通过 USB 暴露的 Mass Storage（固件升级/参数设置用的程序镜像）

## 2. 阶段一：静态侦察

1. **定位镜像**：设置程序为 104,592 字节的裸固件，加载基址 `0x080E0000`，
   向量表 SP=`0x20020000`，确认为标准 STM32 启动布局。
2. **字符串提取**（先于反汇编）：固件内含 GBK 编码中文菜单。提取后出现关键路标——
   `E013 密码高段`、`E014 密码低段`、`产品未注册!`、`您的机器码为:`、`注册码.txt`。
   **逆向的第一课：让二进制先"说话"，人再去听。**
3. **识别 UID 布局**：STM32 96-bit UID 位于系统内存 `0x1FFF7A10/14/18`；
   UID0 为晶圆坐标，形如 `0x00XX00YY`——这是后续判断字节序的锚点。

## 3. 阶段二：定位关键函数

- 以 `E013 密码高段` 字符串的指针为源，做**交叉引用扫描**（字面量池 → `ldr rx,[pc,#imm]`），
  命中菜单处理代码，顺藤摸到注册函数 **`0x80F42A0`**。
- 用 capstone（`CS_MODE_THUMB | CS_MODE_MCLASS`）+ 容错线性扫描（字节滑窗）反汇编。
- 识别辅助例程：
  - `GetData` @`0x80e1564`（按索引读 16 位参数）
  - 64 位整数除法 @`0x80e0bb8`（商 r0:r1，余 r2:r3）
  - 软浮点乘/除/加 @`0x80e0554` / `0x80e07a8` / `0x80e01f0`
  - double→int32/int64 @`0x80e0ad8` / `0x80e0be4`
  - `SetData(25/26)`：注册成功后把机器 ID 写入参数区

**关键信号**：`vmul/vdiv/vadd + double→int` 的组合说明作者刻意用浮点做混淆——
此时任何"整数异或"假设都应被标记为高风险。

## 4. 阶段三：失败的假设（反面教材）

从运行固件源码结构（`G25/G26 == stm32Id1/stm32Id2`）反推出候选组合
（UID2 掩码异或 `0x7E3`），提交设备后**被全部拒绝**。

复盘：那组值是注册成功后固件**写入**参数区的"机器 ID"，不是用户**输入**的密码——
方向搞反了。真正的比较指令在 `0x80F4522`（`cmp` 流水线输出 vs E013/E014）。

> **教训：顺着"写入值"倒推"输入值"必错；必须找到真正的那条 `cmp`。**

## 5. 阶段四：仿真定案

安装 Unicorn CPU 模拟器，写一个最小 harness：

```
map(0x080E0000, 固件)          # 镜像
map(0x1FFF7000, 0x2000)        # UID 区, 写入真实 UID
map(0x20000000, 0x20000)       # RAM + 栈
r8 = 0x1FFF7A18                # 预设(跳过加载指令)
start(0x80F43C0 | 1)           # Thumb 模式: PC 最低位置 1
```

从 `0x80F43C0` 开始逐条执行真实指令，在 `0x80F4492`（sb=UID2^UID1^UID0）与
`0x80F4522`（密码比较处）设 hook 抓值。

**第一次运行，仿真输出的"机器码"与设备屏幕显示值逐位相同。**

## 6. 阶段五：公式化与双通道验证

由指令流归纳出纯函数（见 [README](../README.md#how-it-works)）：

```
d = (double)X × 11.0 ÷ 7.0 + 11160725.0     # 常量在固件 0x80F4700
n = (int64)d ; R = n mod 1e8
v = R/10 + (R%10)*1e7                        # 末位数字旋转
E013 = int((v div 10000) / 2.5) ; E014 = int((v mod 10000) / 2.5)
```

**双通道互验**：

| 通道 | 方法 |
|:--|:--|
| A | Unicorn 逐条执行真实固件指令 |
| B | 纯 Python 复刻公式 |

两台已知设备、四个数字，两通道结果一致；开机回归 `--selftest` 全部 PASS。
此外任意新设备可用 `--firmware` 触发 A 通道复核。

## 7. 字节序：唯一需要外部确认的环节

UID 内存布局（小端）与工具显示（大端、高字在前）不同：

```
内存:  0x1FFF7A10=UID0(晶圆) 0x1FFF7A14=UID1 0x1FFF7A18=UID2
显示:  "53483643 53303606 003F0037"  (高字在前)
```

判定方法：**设备自己会报答案**——未注册时屏幕显示的机器码即 `UID0^UID1^UID2`。
仿真输出与之逐位一致 → 字节序假设成立。不需要猜。

## 8. 结论要点

1. 字符串 → 交叉引用 → 函数边界，是最快的定位路径；
2. 看到软浮点就别猜整数公式；
3. **"让它跑" 胜过 "我猜它"**：CPU 模拟器把"猜测空间"压缩到零；
4. 设备自身的显示输出（机器码）是最可靠的外部校验锚点；
5. 所有推导都要有**闭环验证**（仿真 ↔ 设备显示 ↔ 公式三方一致）才可交付。
